# フェーズ 3a: ブロック検出（実装中）

UI で選んだ色のブロックを缶に入れるタスクの、認識部分です。

## 要件

**テーブルの色と照明が環境ごとに変わっても動くこと。** リグは移動し、その場のテーブルは色もテクスチャも毎回違います。そのため「背景は明るい木目」という前提をどこにも埋め込めません。

**リアルタイムであること。** カメラは 20 fps なので、推論はそれより十分速い必要があります。

## しきい値処理では不可能

まず素朴な HSV しきい値を実カメラ画像で試し、通用しないことを確認しました。

| 対象 | 色相 H | 彩度 S | 明度 V |
|---|---|---|---|
| テーブル（木目） | 11 | **96** | 213 |
| 赤ブロック | 3 | 208 | 202 |
| **青ブロック** | 118 | **77** | 78 |
| 紫ブロック | 169 | 124 | 71 |

**青ブロックの彩度（77）はテーブル（96）より低い**ため、彩度では分離できません。木目の色相はオレンジ帯に入るため、色相でも分離できません。さらに、テーブルがブロックと同系色の環境では色ベースの手法は原理的に破綻します。

## 学習ベースの検出器

YOLO11n を、合成データで学習させます。

汎化性能は**学習データの分布**で作り込みます。しきい値を環境ごとに調整するのではなく、変動をデータに含めてモデルに吸収させる方針です。

### ブロックの切り出し

`img/` の 3 枚（4284x5712）から 36 個（6 色 × 6 個）を RGBA で切り出します。この写真は正対・適正露出で、ブロックの彩度が木目より十分高いため、ここでは色分離が成立します。

色クラスは決め打ちせず、実測の色相分布から決めました。6 つのクラスタが明確に分離しています。

| 色相（OpenCV 0-179） | 個数 | クラス |
|---|---|---|
| 1.5–2.2 | 6 | red |
| 6.1–8.3 | 6 | orange |
| 26.9–28.9 | 6 | yellow |
| 43.3–47.1 | 6 | green |
| 105.5–107.8 | 6 | blue |
| 120.7–123.1 | 6 | purple |

**切り出しではテーブルの影を除去しています。** 影になった木目は暗くても彩度が高く、しきい値を通過します。これを合成に使うと元のテーブルの画素が新しい背景に貼り付き、「テーブル色を変えても動く」という要件に真っ向から反します。

除去は Lab 色空間の色度（a/b）距離で行います。陰影は明度 L を変えるだけで色度をほとんど変えないため、ブロック自身の陰った面は残しつつ影だけを落とせます。明度の下限を併用しています。

### 合成シーン

| 要素 | 内容 |
|---|---|
| 背景（手続き生成） | 単色・グラデーション・筋目・まだら模様を任意の色相で |
| 背景（実写） | 実カメラ 140 枚。アーム、缶、テーブルの縁、ケーブル、床、オフィス風景 |
| 妨害物 | 彩度は高いが立方体でない図形（円・楕円・多角形） |
| 配置 | 0〜16 個、重なりあり、画面端の見切れあり、影付き |
| 撮像条件 | 露出・コントラスト・WB・ガンマ・周辺減光・ノイズ・ボケ・JPEG 劣化 |

**背景にはブロックと同系色のものも含めます**（赤いテーブルに赤いブロックなど）。色だけに依存せず立方体の形状も手がかりにするよう強制するためです。妨害物も同じ狙いです。

**実写背景は必須です。** 手続き背景は色とテクスチャの幅は稼げますが、実シーンにある白いアーム・金属の缶・テーブルの縁・ケーブルが一切含まれません。学習で一度も見ていない物体を検出器がブロックと呼ぶ理由はいくらでもあります。ラベルなしの背景として与えることで明示的に否定を学習させます。

撮影は `scripts/capture_backgrounds.py` で行います。**アームが自動で姿勢を巡回**するので、多様な姿勢が均等に入ります。ブロックは必ず全て片付けてください。写り込んだブロックは「これはブロックではない」という学習信号になります。

ブロックのサイズ範囲（16〜80 px）は実際の視野での実測値（20〜60 px、中央値 35）に合わせています。

### 学習時の注意

Ultralytics の拡張のうち、**色相の拡張は抑えています**（`hsv_h=0.01`）。色がクラスそのものなので、大きく振ると赤が橙になり、汎化ではなくラベルノイズになります。幾何変換とスケールは有効のままです。回転は 180° まで許可しています（ブロックは任意の向きで置かれます）。

## 検証について

**合成データの検証スコアは、生成器への適合度しか測りません。** 判断材料は実カメラ画像での結果です。`scripts/eval_detector.py` がライブで検出させ、推論速度も実測します。

## カメラ設定

自動露出のままだと、フレームごとに同じブロックが違う色に写ります。実測では俯瞰カメラの彩度中央値が自動で 10、露出固定で 123 でした。

一方で固定値を焼き付けると、明るいテーブルに合わせた値は暗いテーブルで破綻します。そこで**起動時に環境へ合わせて決めてから固定**します（`"exposure": "auto"`）。露出を 8 段階振り、白飛び・黒潰れを避けつつ中間調に最も近い設定を選びます。

**ホワイトバランスは自動のままにします。** 固定すると EMEET で赤が極端に強くなり（R-B +25 → +124）、`CAP_PROP_WB_TEMPERATURE` では戻せません。チャンネルゲインが別管理のためです。フレーム間のばらつきは学習時の WB 拡張で吸収します。

順序に注意が必要です。**露出と WB はフォーマット設定の後に適用します。** MJPG 800x600 への切り替えでグラフが再構築されると設定が失われ、かつ校正が既定の 640x480 に対して行われてしまいます。

## 手順

```bash
uv run scripts/extract_blocks.py                    # img/ から 36 個を切り出し
uv run scripts/capture_backgrounds.py               # 実背景を撮影（ブロックは片付ける）
uv run scripts/build_dataset.py --train 6000 --val 600
uv run scripts/train_detector.py --epochs 100 --batch 32
uv run scripts/eval_detector.py                     # 実カメラで評価と速度計測
```
