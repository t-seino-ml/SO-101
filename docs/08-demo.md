# 展示デモ（Slot 方式）

高校生向けの展示用に、**色を指定するとロボットがそのブロックを取って缶に入れる**システムです。

研究開発中の新スタック（TCP / ray-plane / PickPlanner / R1〜R7）は**一切使いません**。
それらは `real-validation` branch に保存されています。

---

## 明日、会場で行うこと（5 分）

この順にやれば展示を始められます。**軌道を作り直す工程はありません。**

### 1. 展示マットを置く

ロボット・Slot・缶の**相対位置**が昨日と同じであることが唯一の条件です。
マットのマーキングに合わせて置いてください。

### 2. ロボットを ROBOT 印へ

ベースが机に**密着**していることを確認。浮いていると全体がずれます。

### 3. 缶を CAN 印へ

### 4. カメラを設置

**カメラの位置は昨日と違って構いません。** 6 つの Slot と、その上のブロックが
画面に入っていれば十分です。近すぎず、Slot どうしが画像上で離れて見えるほうが
判定は安定します。

```powershell
uv run scripts/find_cameras.py --no-preview
```
で `EMEET`（側面カメラ）が見えることを確認。見えなければ USB を挿し直します。

### 5. Slot を登録し直す（**明日やる校正はこれだけ**）

```powershell
uv run scripts/calibrate_demo_slots.py --slots 6 --detect
```

カメラ画像が開くので、**Slot1 から Slot6 まで順に中心をクリック** → ENTER で保存。

- `BACKSPACE` で 1 つ取り消し、`ESC` で中止
- 各 Slot に描かれる円が「この中なら同じ Slot」の範囲です
- **円が重なる場合は自動で半径を詰めます。** 手で計算する必要はありません

クリックの順番が Slot 番号になります。`data/demo_slots/slot1.json` を教示した場所を
最初にクリックしてください。

### 6. 見えているか確認

```powershell
uv run scripts/demo_slot_pick.py --color blue --dry-run
```

ロボットは動きません。`→ slot2（中心から 23 px）` のように出れば OK。

### 7. Slot1 で 1 回テスト

```powershell
uv run scripts/demo_slot_pick.py --slot 1
```

### 8. 展示開始

## 展示中に使うコマンド

### Level 1 — 本命（色だけ言えばよい）

```powershell
uv run scripts/demo_slot_pick.py --color blue
```

カメラが blue を探し、どの Slot にあるか判定して、その軌道を実行します。
**色と Slot の対応は固定していません。** ブロックを入れ替えれば、そのとおりに追随します。

Slot は 6 つあります（`--slot 1` 〜 `--slot 6`）。

### Level 2 — Slot 判定が怪しいとき

```powershell
uv run scripts/demo_slot_pick.py --color blue --slot 3
```

色が見えていることだけ確認し、**Slot は人が指定**します。
Slot の登録がずれていても動きます。

### Level 3 — 最終保険（カメラを一切使わない）

```powershell
uv run scripts/demo_slot_pick.py --slot 3
```

**カメラ・YOLO に何が起きてもこれは動きます。** 困ったらこれに切り替えてください。

### 共通のオプション

| オプション | 効果 |
|---|---|
| `--dry-run` | 見て、選んで、計画を出すだけ。**動きません** |
| `--step` | waypoint ごとに ENTER を待つ。初回確認用 |
| `--speed 0.6` | ゆっくり動かす（0.6 倍速） |

## 動かないとき

### ロボットが「動きません」と言って止まる

**これは正常な動作です。** 理由が必ず表示されます。

| 表示 | 意味 | 対処 |
|---|---|---|
| `blue のブロックが見つかりません` | その色が見えていない | ブロックを置く／照明を明るく |
| `blue のブロックが Slot の上に見つかりません` | 色は見えるが Slot の外 | Slot の印に合わせて置く |
| `Slot の上に 2 個あります` | 同じ色が 2 つの Slot にある | 1 個だけにする（Slot の外にある分は無視されます） |
| `いちばん近い Slot まで N px あります` | ブロックが Slot の上にない | Slot の印に合わせて置き直す |
| `slot1 と slot2 のちょうど中間にあります` | どちらか判断できない | Slot の中心へ寄せる |
| `検出位置が N px ばらついています` | 検出が不安定 | 照明／カメラの固定を確認 |

いずれも **Level 2 か Level 3 に切り替えれば動きます。**

### 途中で止まった

```
  *** 中断: ... ***
  その場保持: Goal_Position を現在位置へ書き換えました（トルクは ON のまま）
```

**アームは落ちません。** その場で保持されます。

1. 何が起きたか見る（ブロックの位置、ぶつかっていないか）
2. 障害物をどけて、もう一度実行

### アームを止めたい

| | 方法 | 結果 |
|---|---|---|
| 1 | **Ctrl-C** | 指令を止めてその場保持。落ちません |
| 2 | 別ターミナルで `uv run scripts/torque_off.py COM4` | トルク解放。**アームは落ちます** |
| 3 | 電源を落とす | **アームは落ちます。先に支えてください** |

### サーボが「応答しません」と言われる

過負荷保護が働いています。**電源を入れ直す**と復帰します。

## 仕組み（聞かれたとき用）

```
色を指定
  ↓
外付けカメラで 7 フレーム撮影
  ↓
学習済み YOLO が指定色のブロックを検出（7 枚の中央値をとる）
  ↓
画像上で、6 つの Slot のうちどれに近いか判定
  ↓
その Slot 用の「人が教えた軌道」を再生
  ↓
Pick → 缶へ運ぶ → Drop → Home
```

**ロボットの動きは計算していません。** 人がリーダアームで動かして「ここ」と教えた
関節角度を、そのまま再生しています。だからカメラが動いても動きは変わりません。

カメラがやっているのは「**6 つのうちどれか**」を選ぶことだけです。

Slot の外に置いてあるブロック（予備、缶の中、机の隅）は候補に入りません。

## 軌道を作り直したくなったら

会場で作り直す必要はありませんが、Slot の位置を物理的に変えた場合は：

```powershell
uv run scripts/teach_demo_slot.py --slot 2
```

リーダアームで 9 つの姿勢を順に作り、各々で ENTER。
`HOME → PREGRASP → GRASP → CLOSE → LIFT → TRANSFER → CAN_ABOVE → DROP → RETURN`

**コツ**
- **GRASP と CLOSE で腕を動かさない**（顎だけ閉じる）
- **CLOSE は実際にブロックを掴んでから** ENTER
- **LIFT は真上へ**
- **CAN_ABOVE / DROP / RETURN は全 Slot で同じ姿勢**に揃える
- **RETURN は HOME と同じ姿勢**に

教示後は必ず：
```powershell
uv run scripts/demo_slot_pick.py --slot 2 --step --speed 0.6
```

## 安全の作り

展示中も、以下はすべて効いています。

- **waypoint ごとに到達を確認**してから次へ進む（±2.5°）
- 届かないときは**指令を足し直す**（自重でたわむ分の補正、最大 3 回・8° まで）
- **3° 以上の誤差**が補正しても縮まなければ「何かに当たっている」として停止
- **アーム関節**の負荷 > 450 で停止（グリッパは握るのが仕事なので別枠）
- 温度 > 55 °C で停止
- 移動は **30°/s を超えません**（教示時の時間が短すぎても自動で伸ばします）
- 通信が乱れても **4 回まで再試行**。本当に切れていれば停止
- 停止時は **Goal_Position を現在位置へ書き換えて保持**（落ちません）
- 実行前に**全 waypoint がサーボの可動限界内か**を確認
- 最初の waypoint が現在姿勢から 120° 以上離れていたら**実行しない**
