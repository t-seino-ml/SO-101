# フェーズ 5: UI・統合アプリケーション（未着手）

> このドキュメントは**計画**です。UI フレームワークも未決定です。

## 目的

フェーズ 1〜4 を 1 つのアプリケーションに統合し、コマンドラインを意識せずに操作できるようにします。

## 想定する機能

- 接続状態の表示（ポート、サーボ、電圧、温度）— `scripts/diag.py` の内容を画面に
- キャリブレーションの実行と状態確認
- テレオペレーションの開始・停止、パラメータ調整（fps、P ゲイン）
- カメラ映像のプレビュー
- データ記録の開始・停止、エピソード一覧
- 学習済みポリシーの選択と自律実行、緊急停止

## UI フレームワークの選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| FastAPI + ブラウザ | 別 PC からアクセス可能、デモ向き | 実装量が多い |
| Gradio | 最短で動く、HuggingFace エコシステムと相性が良い | 細かいレイアウト調整が苦手 |
| PyQt / Tkinter | カメラ・USB へのアクセスが直接的、ネットワーク不要 | 配布とレイアウトが面倒 |

**未決定です。** 決まるまで `src/so101/ui/` にフレームワーク依存のコードは置きません。

## 構造の方針

- `src/so101/ui/` — フレームワークに依存しない部分。状態モデル、表示用の整形、ロボット状態の読み取りビュー
- `app/` — フレームワーク依存の実装とエントリポイント

こう分けておけば、フレームワークを乗り換えても `src/so101/` 側は影響を受けません。

## 安全面

UI からロボットを動かせるようにする以上、**画面上の緊急停止と、物理的な非常停止の両方**が必要です。ブラウザ UI の場合、ネットワークが切れた時にロボットが動き続けない仕組み（ハートビート）も要ります。
