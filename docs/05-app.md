# 画面

展示はコマンドラインからは動かしません。1 つ起動するだけです。

```bash
uv run app/demo_ui.py          # F11 で全画面、Esc で戻る
```

ホーム画面で 2 つのモードを選びます。

| モード | 中身 |
|---|---|
| **リーダ機で動かす** | リーダ機の姿勢にフォロワが追従するだけ。モデルも検出も軌道も使いません |
| **ブロックをつかむ** | 色を選ぶと、検出 → Slot 判定 → 教示軌道の再生でブロックが缶に入ります |

どちらの画面にも外付けカメラとアーム搭載カメラの映像が出ます。ブロックをつかむ側には
検出結果（バウンディングボックスと Slot の円）を重ねた 3 枚目が加わります。

## なぜ Tkinter か

標準ライブラリに入っていて、カメラとシリアルポートを直接触れるからです。サーバも
ブラウザも要りません。**会場で止まりうるものが 1 つ減ります。**

角丸もグラデーションもアイコンも Tk にはないので、各画面はウィジェットを並べるのでは
なく 1 枚の Canvas に描いています。描画部品は [`app/theme.py`](../app/theme.py) に
まとまっていて、配色はそこだけ直せば全画面に効きます。

## 構造

```
app/
├── demo_ui.py     画面の構成、レイアウト計算、ワーカーとの受け渡し
└── theme.py       背景・角丸カード・カメラアイコン・立方体・STOP の描画
```

- **レイアウトは計算します。** `pick_layout()` と `teleop_layout()` はウィンドウの
  幅と高さから各カードの矩形を返す純粋な関数で、テストがこれを 1280×720 から
  1920×1080 まで検証します。映像パネルはヘッダと下段カードの残りを全部使います
- **アームを動かす処理は必ずワーカースレッドです。** 結果は `queue.Queue` で戻し、
  Tk はメインスレッドからしか触りません
- **ロボットはモードに入ったときに接続し、出たときに切断します。** 誰も見ていない
  あいだにアームが通電したままにはなりません

## 止め方

3 系統あり、性質が違います。

| 手段 | 効き方 |
|---|---|
| 画面の **STOP** | いまの waypoint の区切りで止まります。**最大 3 秒かかります** |
| `uv run scripts/torque_off.py COM4` | 別ターミナルから。その場で保持してトルクを切ります |
| 電源 | 即座 |

**画面の STOP は緊急停止ではありません。** 会場では `torque_off.py` を打てる
ターミナルを 1 枚開いたままにしておきます。詳細は [08-demo.md](08-demo.md)。
