# フェーズ 3: デモンストレーション記録

リーダー機で「ブロックをつかむ」動作を実演し、LeRobot データセットとして記録します。
学習するのは**色に依存しない 1 つのスキル**だけです。どのブロックを狙うかは
ポリシーの外側（側面カメラの物体検出 + 粗い移動）で決めます。

## なぜこの構成か

スクリプト化した逆運動学によるピック&プレースは断念しました。誤差の連鎖
（側面カメラの視差 + グリッパ座標系の定義 + 下向き姿勢での可到達範囲）が
実測で数 cm 残り、ジョーがブロックを挟める位置に入らなかったためです。

代わりに役割を分けます。

| 担当 | カメラ | 求められる精度 |
|---|---|---|
| どの色のブロックか・だいたいどこか | 側面カメラ（外付け） | ±2〜3 cm |
| つかむ動作そのもの | アーム搭載カメラ（手首） | ポリシーが視覚で閉ループ |

手首カメラはアームに固定されているので、**実験場所や外付けカメラの位置が
変わっても見え方が変わりません**。ポリシーを手首カメラだけで駆動する理由が
これです。側面カメラを入力に加えると、その設置位置に学習が縛られます。

## 記録

```powershell
uv run scripts/record_demos.py --episodes 30
uv run scripts/record_demos.py --episodes 10 --resume   # 追加で記録
```

`lerobot-record` をこのリグ用に包んだものです。`bus_patch`（リトライ・
パケットタイムアウト）と `tuning`（P ゲイン）を先に適用し、`cameras.json`
のカメラを役割名で開き、`push_to_hub=False` でローカルにのみ保存します。

保存先は `data/demos`、repo_id は `so101/grasp_block`。

### エピソードの取り方

**毎エピソード、グリッパをブロックの数 cm 手前に置いた状態から始めます。**
実行時に粗い移動が残していく位置がそこだからです。テーブルの反対側から
始めると「探索」を学習してしまい、それはこのポリシーの仕事ではありません。

1 エピソード = 近づく → 閉じる → 持ち上げる → 缶に落とす。ブロックの色と
置き場所はエピソードごとに変えます。

キー操作: 右矢印でエピソード終了、左矢印で直前をやり直し、Esc で中断。

### 実績

30 エピソード / 15,251 フレーム / 30 fps。`observation.images.wrist` と
`observation.images.side` を両方 800x600 で記録しています（side は保険として
残してあるだけで、学習には渡しません）。

30/30 エピソードが「グリッパが閉じた後にアームが動く」= 把持成功で終わって
いることを確認済みです。
